### Pre-Push-Hook und GitHub-Workflows

- Georg zeigte den Pre-Push-Hook. Vor einem Push laufen `npm ci`, `npm run lint`, `npm run typecheck` und `npx vitest run`. Schlägt der Gate-Lauf fehl, wird der Push verhindert; offensichtlich kaputter Code gelangt so erst gar nicht ins Repository. Nach einem Fehler muss weiterprogrammiert werden, bis der Lauf wieder grün ist.
- Anschließend ging Georg durch die GitHub-Workflows: Bei einem Push auf `master` wird der Produktions-Workflow auf dem BOKU-Server ausgeführt. Die dortigen Docker-/Release-Schritte veröffentlichen die neue Version; die Applikation wird dabei upgegradet.
- Der Workflow `test.yml` läuft auf Georgs neuem Server. Die Skripte sind bereits weitgehend vorbereitet; das Team muss sich um deren Details vorerst nicht kümmern.

### Datenschutz, LLM-Nutzung und lokale Entwicklung

- Die BOKU wünscht ausdrücklich, dass die Daten nicht öffentlich sind. Dem wird durch das private Datenprojekt und den geschützten Zugang zur Anwendung Rechnung getragen: Weder eine öffentliche Website noch ein öffentliches Repository sollen die Daten einsehbar machen. Die Anwendung ist hinter einem Admin-Login bzw. einer Anmeldung geschützt.
- Die nachgefragte Nutzung von KI bzw. LLMs ist unter diesen Voraussetzungen erlaubt; entscheidend ist, dass die Daten dadurch nicht öffentlich werden.
- Alle Teammitglieder sollen die Anwendung bei sich lokal einrichten, damit sie direkt hineinschauen und entwickeln können. Georg verwies darauf, dass ein Agent dieses Setup in etwa 20 Minuten erledigen könne.
- Für den Server besteht zusätzlich die Möglichkeit eines SSH-Zugangs mit dem Benutzer `catchlogx`. Die Nutzung ist optional und nicht zwingend erforderlich.

## Decisions

- **Keine neue Eingabe-App zum jetzigen Zeitpunkt:** Die bewährten Excel-Templates bleiben die Dateneingabe. Eine Alternative wird erst bei konkretem Bedarf der BOKU entwickelt.
- **Keine feste Ticketquote für Alex:** Das Projekt bleibt ein Work in Progress; nicht erledigte Arbeit bleibt offen. Auch „alle aktuell offenen Tickets bis zum Ende der Diplomarbeit“ ist keine verbindliche Zielvorgabe.
- **Armin bleibt eingebunden:** Er ist weiterhin Collaborator und darf Tickets bearbeiten. Kommt er bis Jänner/Februar bzw. spätestens März nicht in die Gänge, wird es eine Lehrabgabe.
- **Daten bleiben nicht öffentlich:** Der Zugang erfolgt nur über geschützte Bereiche und Anmeldung. Die Nutzung von LLMs ist unter dieser Voraussetzung erlaubt.
- **R-Zugriff ist read-only:** Die statistische Auswertung erfolgt direkt über PostgreSQL mit einem Read-only-Benutzer; Schreibzugriffe bleiben dem Admin-Tool und den Excel-Uploads vorbehalten. Georg und Dominik übernehmen das Thema gemeinsam (#153).
- **Offizielle Fischarten werden als JSON unter `assets/` gepflegt:** Die kanonische Liste wird mit Lena bereinigt und nicht dauerhaft als Datenblock innerhalb eines Skripts geführt.
- **Keine strenge Stundenkontrolle:** Agentenunterstützung und effizientes Arbeiten sind akzeptiert; Qualität und Nutzen gehen vor reiner Zeit- oder Zeilenmenge.
